# Unpaid checkout attempts

Customer history, active-order lookup, Admin customer profiles and customer order counts now include only PAID, PARTIALLY_REFUNDED and REFUNDED payments. Existing unpaid records are excluded immediately without destructive SQL. The Admin order inbox already applied this filter. Creating a checkout draft and receiving a failed/canceled Stripe payment now emit checkout-specific customer events, not operational order notifications to Admin.

POST /payments/abandon authenticates the customer and scopes the draft by owner. A pending PaymentIntent is verified and, if still awaiting payment/action/confirmation, canceled with reason abandoned. Processing payments and authorizations are preserved. Successful payments are reconciled using the existing verifier. A successful Stripe cancellation is required before a reserved voucher can be released. Database row locks, the customer-credit lock and an idempotency key prevent duplicate release; only an owned, still-pending attempt is closed. No cancellation fee or courier payout applies to this checkout closure. Financial audit records remain stored internally.

PaymentIntent binding now requires the order to remain pending and retain its previous intent ID, preventing an in-flight checkout request from attaching a new intent after abandonment. Closing the Flutter payment page calls abandonment; the checkout owner also makes a best-effort cleanup on disposal. An abandoned attempt is never reused on the address page. Network failures or app termination cannot make drafts visible because visibility is enforced independently in server queries. If a payment is processing, it appears in the order history only after server confirmation. Paid and refunded orders remain visible.

No migration, table reset or deletion of paid orders. Stop only Nest with Ctrl+C and run scripts/update-checkout-drafts.ps1. It generates Prisma, builds API and Android, starts Nest again, checks database health and installs the APK with existing data preserved. Existing language assets are reused.

Validation here: Dart syntax parsing; TypeScript transpilation; seven isolated behavior checks exercising the actual abandonment method with mocked Stripe/database boundaries. Full Nest compilation and Flutter build require the user's installed project environment and are performed by the updater. No real Stripe payment or database transaction was executed here.
